Built on Next.js App Router under `app/`: `layout.jsx` provides the root shell (Navbar + main + Footer) and global metadata; route segments (`page.jsx`, `admissions/page.jsx`, `cbt/page.jsx`, `contact/page.jsx`, `exam/page.jsx`) compose page-level layouts from reusable UI fragments. Shared presentational components live in `components/` (Hero, Programs, About, Facilities, Gallery, Testimonials, News, Faq, Navbar, Footer). Data access is centralized in `lib/`: `supabaseClient.js` exports a Supabase anon-key client plus a `settingFileUrl` helper for public storage objects; `useSettings.js` is a shared client hook that reads the single `jmis_settings` row every section consumes; `enquiry.js` exposes `submitEnquiry` and `submitApplication` which insert rows into `jmis_enquiries` / `jmis_admissions_applications` and then fire-and-forget an email via the server-only API route `app/api/notify/route.js`. Dependency direction is one-way: pages → components → lib → Supabase; the API route is the only server-side boundary and keeps SMTP credentials off the client bundle.
